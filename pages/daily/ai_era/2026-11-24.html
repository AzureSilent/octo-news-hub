11月17日，微软在Ignite上直言：「仅仅让模型访问信息，远远不够。」

Karpathy早就预言：纯RAG只是「查询时现拼」，知识根本无法沉淀，大模型需要一个「LLM Wiki」式的企业级可信知识库基础设施。

如今，硅谷大厂正在把这个理念疯狂变现。风向彻底变了：从「现拼型检索」走向「编译型知识」。

但Anthropic也结结实实翻了车：一份57条事实的合同，AI总结后只剩41条。强制「一合同一页、逐字引用」后，准确率才回到100%。

这揭穿了企业级AI的谎言——「语义相关」不等于「事实可靠」。合同条款都能丢，谁敢把核心业务交给Agent？

企业知识库的地狱难度，不在吞吐量，而在「证据可核验」。

沿这条硬核路线，国内AI原生企业海马云（haimacloud）推出lumimax，定位为面向Agentic AI的企业级可信知识库系统。

它试图解决的正是：让企业海量、分散的文档资料，转化为AI能够持续调用、跨文档推理，并且可以追溯原始依据的专业知识资产。

成立于2014年的海马云，依托自主研发的云计算与实时渲染技术，已为全球超3000万用户提供超低延迟实时云渲染服务。

早在今年3月，海马云依托自身算力与技术优势，就已经开始布局Agent领域，推出了AIGC全能内容创作平台RunningHub。

从文档检索到知识深度编译：lumimax试图改变什么？

传统RAG的基本逻辑是切分文档、建立索引、检索片段、生成答案。

lumimax采取了另一种思路：不只是把文档切成可以检索的知识片段，而是先对资料进行深度解析，再将其中的实体、事件、关系、事实和证据组织起来，形成统一的语义体系。

简单来说，就是把一堆彼此分散的文档，转化为一张能够被AI理解和计算的知识网络。

这背后涉及一条完整的技术链路：原始资料 → 深度解析 → 知识抽取 → 关系构建 → 跨文档推理 → 证据核验。其中，lumimax的核心技术是深度证据链知识网络（DEN）。

DEN不只是传统意义上的知识图谱。它试图在实体、事件和关系之外，进一步保留支持这些知识的原始证据，使知识关联与事实依据能够建立连接。

例如，企业上传了几十份合同、补充协议和会议纪要。传统检索系统可能分别找到每份文件中的相关条款，但当用户询问某项业务约定是否发生变化时，系统需要进一步识别不同文件之间的关联、时间顺序和条款冲突。

lumimax希望将这些分散的信息组织成可计算的知识体系，再沿着实体、关系和证据进行推理。

由此带来四项能力：

  • 跨文档关联： 从多份资料中建立实体、事件和事实之间的联系。
  • 多跳推理： 沿着知识关系逐层推导，而不是只匹配关键词。
  • 冲突检测： 识别不同资料之间不一致的信息，辅助用户核查。
  • 证据溯源： 将推理结论关联到原始文档及其出处，方便验证。

值得注意的是，这种技术路线并不意味着RAG已经失去价值。检索依然是知识调用的重要环节，知识图谱也并非天然可靠。

真正的挑战在于，如何把检索、知识组织、推理与证据核验结合起来，让知识不再是一次性消费的信息片段，而是可以持续维护的资产。

这也是lumimax试图建立的技术差异化。

霸榜8项国际权威基准测试，复杂知识处理能力被全面验证

在全球8项极具挑战性的Benchmark公开评测中，lumimax斩获了全部最高分。

这些测试并非简单考查模型能否回答常识问题，而是覆盖企业知识处理中最具挑战性的几个环节：长文档理解、跨文档推理、复杂关系识别、图文信息解析以及高噪声环境下的知识抽取。

这套测评覆盖全面且直击痛点，囊括了FRAMES、RAMDocs、NoLiMa · 32K、GraphRAG-Bench、MultiHop-RAG、OpenDocVQA、ViDoSeek和WildGraphBench共8项国际权威基准，涵盖长文档检索、冲突消歧、多跳推理与图文理解等核心能力。

第一关：跨文档推理，能否把分散信息串起来？

FRAMES由Google DeepMind提出，每道题都要综合2至15篇分散资料完成检索、多跳推理与事实核验，是测试AI深度研究、深度搜索能力的权威Benchmark。

它考验的不是模型能否找到一段相关文字，而是能否把不同资料中的信息组织起来，最终得出有依据的答案。

这份榜单之所以硬核，是因为lumimax不仅凭92.84%拿下第一，还力压Tongyi DeepResearch（90.60%）、GPT-5（86.00%）等全球一线旗舰等。

第二关：面对矛盾和噪声，能否避免错误结论？

在多文档冲突检测与防幻觉测评RAMDocs上，lumimax斩获45.29%（超第二名10个百分点）。

你可能疑惑：45.29%连及格线都不到，怎么还排第一？

因为RAMDocs直接还原了让人头疼的「脏数据现场」——文档自带歧义、暗藏错误、噪音遍地。

这个数字乍看并不高，但RAMDocs的评价标准相当严格：不仅要求找到正确事实，还要求答案满足精确匹配，遗漏关键信息或引入错误内容都可能导致失分。

比如用户问「迈克尔·乔丹取得了哪些成就」，资料库里既有篮球巨星，也有机器学习泰斗，系统必须完成身份消歧，避免将两个人的信息混在一起。

第三关：长文档深度理解，能否摆脱关键词依赖？

在长文档深度解析与语义关联上，lumimax三线登顶——NoLiMa·32K得分90.52%、OpenDocVQA得分91.45%、ViDoSeek得分81.23%，完胜GPT-4等国际顶尖模型。

NoLiMa·32K专门设计了关键词重合度较低的测试问题，考验模型能否在长上下文中理解语义关系，而不是依赖简单的关键词匹配。

比如资料写「张三去过故宫」，你问「谁去过北京？」。没了拐杖，32K长文档下13个主流模型11个准确率不到一半，测试的GPT系列也不到80%，而lumimax稳拿90.52%。

对于财报、研究报告、PPT等大量采用图文混排的企业资料而言，理解一份文档不只是提取文字，还需要保留图表与上下文之间的关联。

在视觉文档理解方面，lumimax在OpenDocVQA和ViDoSeek中分别取得91.45%和81.23%。

第四关：高噪声环境下，能否从杂乱信息中提取有效知识？

最后，在高噪环境非结构化抽取测试WildGraphBench上，lumimax以77.39%夺冠。

真实世界的数据并不像标准数据集一样整齐，往往混杂着重复内容、无关信息和不完整的上下文。WildGraphBench就是针对这类复杂环境设计的评测——用4550万Token真实网页、博客、杂乱PDF和公开报告，考查真实资料环境下的信息查找与综合作答。

Benchmark成绩并不等同于真实业务中的准确率。不同系统的模型配置、数据处理方式、评测协议和计算成本，也会影响最终结果。但至少，这些测试为判断lumimax的复杂知识处理能力提供了一组可量化的参考。

企业需要的是可控的专业知识资产

当我们将目光从产品功能拉升到行业格局，就会发现lumimax的诞生，绝不仅仅是一次工具的发布，更是关乎企业「主权AI（Sovereign AI）」战略落地的关键卡位。

在使用大模型时，当下企业有一个致命悖论：通用大模型很聪明，但它不懂我的企业业务。

如果我想让它懂，我就得把核心的财务数据、客户合同、研发机密传给公有云模型，敏感数据安全与核心知识自主控制又没办法保证。

「AI主权」，即个人基于个人资料、企业基于企业资料来构建和掌控AI的能力。而知识库，就是主权AI的核心上下文与护城河。

lumimax完美承接了这一战略命题。

它支持企业级私有化部署，帮助企业将庞杂的、持续更新的资料，沉淀在自主可控的安全环境中。它支持断点续传和增量更新，资料库随着企业发展不断「生长」。

同时，它支持通过MCP，作为「外接知识大脑」接入豆包、WorkBuddy等外部Agent，为Agent提供知识检索与证据溯源能力。

这意味着企业不必将所有专业知识能力绑定在单一AI产品上，而是可以将自己的知识库作为独立的能力模块，接入不同的Agent和业务流程。

你的数据不会成为别人训练模型的养料，而是永远只为你所用的「数字资产」。

准确率随认知复杂度下降：L1 76.2%，L2 63.9%，L3 42.8%。答题者和Agent走的是同一套多阶段流程，仍会选错来源、漏掉细粒度细节，或在很长的检索里注意力中断。57.5%说明的是这一条件下的题目难度，人类准确率也远未饱和。

Acc_adj 最高的通用 Agent 是 Hermes Agent + Gemini 3 Flash，24.0%，PLR 29.0%。开源配置里最高的是 OpenClaw + Kimi K2.5，21.4%，PLR 20.1%。这是 12 个通用 Agent 里 PLR 最低的一项，但不是每个能力族都领先。目前还没有配置达到可让使用者把真实场景中的源文件检索交给 Agent 的准确率。

通用 Agent 的 AIE 最高是 Hermes + Gemini 3 Flash 的 24.8%，AMO 最高是 OpenClaw + GPT-5.2 的 27.8%。ARV 上 Hermes + Gemini 3 Flash 是 32.2%，人类是 33.7%。

换脚手架之后，升降随基座而变。

  • Qwen3.6 Plus 上，Hermes 的 DRV 是 30.1%，OpenClaw 是 13.6%。Acc_adj 是 7.4% 和 0.5%，Hermes 的 PLR 仍为 65.1%。

  • Kimi K2.5 在 OpenClaw 上的 Acc_adj 是 21.4%、PLR 是 20.1%；换到 Hermes 后，PLR 为 83.3%，Acc_adj 为 2.3%。

  • GLM-4.7v 上，OpenClaw 的 Acc_adj 是 5.2%，Hermes 是 2.2%。

更好的脚手架不只是多给工具，还要限制捷径，并保留来自源文件的证据。基座在调用工具和细节定位时的推理，同样影响结果。

能力族上的正确率把捷径也算进去了。OpenClaw + Qwen3.6 Plus 在多数文档和视频族上达到两位数，PLR 为 96.0%，Acc_adj 降到 0.5%。Hermes + Claude Opus 4.6 的文档和视频答案正确率同样不低，PLR 为 89.0%，Acc_adj 为 2.8%。


答对的轨迹分成三类

§4.2 里，研究人员检查了两个基座的正确轨迹：闭源的 Claude Opus 4.6，开源的 GLM-4.7v。每条答对的轨迹按模态归入三类。分类是人工做的，不是 12 个系统的自动统计，也没有按脚手架拆开。每个百分比的分母，是该模态上答对的题数。

表 4（论文 Table 4）。TRUSTED：访问了正确的源 URL，且未访问本地基准文件。FILE-LEAK：轨迹中有读文件或列目录，与寻找评测文件的行为一致；容器内没有基准文件，探测得不到该文件，随后的答案来自参数记忆。WEB-LEAK：使用了搜索，但没有获取标注的源 URL；答案来自搜索摘要、聚合页或 YouTube 元数据。

两个基座都是文档以 FILE-LEAK 为主、视频以 WEB-LEAK 为主，比例不同。

按 Claude Opus 4.6、GLM-4.7v 的顺序：

  • 文档里，TRUSTED 是 5.6% 和 5.1%，FILE-LEAK 是 93.1% 和 82.1%。

  • 视频里，WEB-LEAK 是 73.6% 和 69.4%。

  • GLM-4.7v 的音频里，WEB-LEAK 61.5%，TRUSTED 15.4%。Claude Opus 4.6 没有音频行，与表 3 中音频列为空一致。

FILE-LEAK 和工具暴露有关。脚手架可以拦住对基准目录的探测，并限制无关的文件系统访问。

WEB-LEAK 和媒体工具、指令遵循有关，系统要去看帧、时间戳和音频片段。Shi 等（2025）测的是源文件已经交给模型之后的媒体理解。RDQA 还要求 Agent 自己检索、定位，并在轨迹里留下记录。

Hermes + Claude Opus 4.6与Hermes + GLM-4.7v的Acc_adj是2.8%和 2.2%。两边 PLR 都高，能力族上的答案正确率并不相同。Acc_adj 接近，主要来自脚手架，而不是两个基座本身的多模态能力。

附录闭卷最高只有 0.2%。主实验里这些答对出现在启用了工具的评估中。FILE-LEAK 指的是该次轨迹没有把指定源文件解析进上下文，答案随后来自参数记忆。


参考基线RDQA-Skill

视频和音频上，系统经常用搜索摘要、聚合页或平台元数据，代替对原始媒体的检查。

研究人员在 Hermes Agent 上加了一条证据定位循环（evidence-localization loop），基座是 GPT-5.2，称为 RDQA-Skill，用作参考基线，便于后续工作复现。

图 4（论文 Figure 4）。证据不足就改查源文件的另一部分；证据足够，才输出答案和依据。

给定问题之后，循环有四步。

  1. 缩小范围（scope narrowing）。 用思维链写出证据位置假设：答案最可能在源文件的哪一部分。

  2. 定向工具调用（targeted tool invocation）。 针对这一位置做解析、抽帧或转写。

  3. 抽取候选。 候选从检索到的片段（retrieved span）中抽出，要来自这一片段。

  4. 反思（reflection）。 证据对当前问题的支持不足，例如候选与问题中的约束冲突，就修改位置假设，改查另一部分，并重复循环。支持足够时，输出答案，并附上作为依据的证据。

这条循环在提交答案之前检查原始媒体。ri=1ri=1 记录的就是这件事：下载文件与标注源文件一致，或地址是标注的原始 URL，并且对该文件调用了解析工具。

表 3 里，Hermes Agent + GPT-5.2 与 RDQA-Skill + GPT-5.2 用的是同一个基座。前者 Acc_adj 为 13.8%，PLR 为 57.2%，AIE、AMO 为 18.7% 和 21.3%。后者 Acc_adj 为 41.1%，PLR 为 2.4%，在全部 Agent 配置里 PLR 最低。人类基线的 PLR 是 0.0%。

音频是这条循环主要针对的模态。AIE 为 60.0%，AMO 为 42.5%。其他 Agent 配置在这两列都没有超过 28%。主实验里通用 Agent 的音频差距，主要来自脚手架没有要求对源做转写。

41.1% 仍比人类平均 57.5% 低 16 个点以上。PLR 已经很低，剩下的错误来自细节定位和多步推理。RDQA-Skill 在三个 L3 族上的答案正确率，DRV、VRV、ARV 分别为 41.3%、34.2%、32.5%。DTE 上 Skill 是 42.7%，Hermes + Gemini 3 Flash 是 50.0%。VTE、VMO 上 Skill 是 56.0% 和 44.6%，人类是 88.4% 和 79.7%。因此只把它当作参考基线。


三方面的限制

  1. 每个配置只评估一次，没有方差估计。 系统之间的小差异不宜看成显著的排名。

  2. PLR 是保守估计。 只承认 SHA-256 与标注源文件一致，或 URL 与标注的原始 URL 一致。从另一份合法来源读到同一事实，仍计为泄漏。PLR 因此把捷径的比例估高了，Acc_adj 应看作基于源文件作答能力的下界。

  3. 题目依赖当时可访问的网页。 失效 URL 不计入分数，报告值是可访问子集上的结果。


结论

RDQA 评的是多模态 Agent 能否在开放网页上找到原始文件，调用工具，定位到细粒度证据，再按该文件作答。

这一次评估里，通用 Agent 的 Acc_adj 最高 24.0%，人类平均 57.5%，RDQA-Skill 为 41.1%。各模态差距大，同一基座换上另一种脚手架，升降也不一致。

能力族上的答案正确率把网页摘要、搜索摘要和参数记忆算了进去，会高过按源文件作答的能力。Acc_adj只计入轨迹能够证明指定源文件已被下载、且被解析工具读过的题。
