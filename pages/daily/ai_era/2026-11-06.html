9. EMNLP'26|AI机器人协同设计智能体：每一次试错都留下经验

11-06 18:57 原文链接

新智元报道


AI能否像工程师一样，在反复设计机器人时积累经验？

机器人的身体结构与运动控制紧密相连：驱动器放在哪里、身体怎样保持稳定，都需要通过控制训练与仿真反复验证。这些试错代价高昂，其中的经验却往往没有被整理成可供后续设计复用的知识。

密歇根大学安娜堡分校研究团队提出了AI机器人协同设计智能体Auto-Robotist，相关工作已获EMNLP 2026主会录用并开源。

这里的「协同设计」，指把机器人身体结构的搜索与控制器训练结合起来。系统用大语言模型提出结构改进，为候选机器人训练控制器，再通过仿真检验效果，并将结果整理成下一轮设计可以使用的经验。

论文链接：https://arxiv.org/abs/2605.25832

代码链接：https://github.com/wangyf9/Auto-Robotist

Auto-Robotist的核心是一个持续更新的「技能库」。这里的技能，是如何设计机器人的经验，例如怎样支撑驱动器、避免结构失稳。

实验表明，这些经验能改善EvoGym中七项软体机器人仿真任务的设计搜索，并从5×5网格迁移到10×10的更大设计空间。一个失败的机器人，也能为下一次设计留下有价值的经验。


为什么机器人设计需要记忆

设计机器人的身体结构，面临着巨大的组合空间。以软体机器人仿真平台EvoGym为例，机器人由网格中的单元组成。每个格子有五种状态可选：留空、刚性材料、柔性材料，以及横向或纵向驱动单元。不考虑连通性等约束时，一个10×10网格就有5的100次方种组合。

筛选一个设计也很昂贵：需要先用强化学习算法PPO训练控制器，让机器人学习如何运动，再用仿真评估它的任务表现。文中的「奖励」和「适应度」都用于衡量机器人完成任务的表现得分。

图1｜常规搜索与Auto-Robotist的比较：试错记录能否成为可复用的设计知识

遗传算法（GA）通过保留表现较好的设计、不断生成新变体来寻找更优机器人。它主要在种群和优胜设计中保留搜索成果，通常不会把成功与失败整理成可直接阅读、复用的设计规则。Auto-Robotist希望保留的，正是这些试错背后的经验。图1将这种缺少显式设计知识积累的流程简称为「无记忆搜索」。


让设计经验成为可复用的知识

这项工作的核心想法是：一次搜索可以同时产出好设计和设计知识。Auto-Robotist让大语言模型（LLM）在搜索过程中整理「设计笔记」，从仿真结果中归纳哪些结构有帮助、哪些问题应当避免，再用这些经验指导后续设计。

为了让这些笔记真正有用，技能库遵循三条原则：记录规律，使经验可以在新的设计中使用；保留证据，让规则对应具体的评估记录；允许修订，让新结果能够补充、合并或纠正旧经验。

图2｜Auto-Robotist框架：用已有经验指导设计，再用新实验更新经验

每条设计技能记录什么

如图2所示，每条技能分为三层，分别回答「什么结构有用」「怎样改进」和「依据是什么」。

  • L1原型——什么结构可能有用。记录一种结构及其适用条件，例如围绕驱动器形成支撑的门式框架。

  • L2规则——怎样改进，哪些问题应当避免。正向规则总结有助于提高得分的做法，负向规则记录反复出现的失败模式，并关联支撑证据与效果统计。

  • L3观测——哪些实验支持这些判断。保存具体设计、任务、网格大小、得分和设计来源，便于回查每条规则的依据。

边设计边积累经验

Auto-Robotist反复执行三个步骤，让经验指导设计，也让实验结果更新经验：

  1. 提出设计。从技能库检索相关经验，让LLM据此修改表现较好的已有设计。同时保留GA的随机变异，探索现有规则尚未覆盖的结构。

  2. 仿真验证。先检查候选机器人的各部分是否连通、是否含有驱动单元，再用PPO训练控制器，通过仿真获得任务得分。

  3. 更新经验。将新的结构经验加入技能库（Add），根据评估结果修订规则（Diagnose），并合并重复条目（Merge）。成功和失败的证据都会参与更新。


实验如何比较

任务覆盖七种能力。实验在EvoGym的行走（Walker）、过桥（BridgeWalker）、平衡（Balancer）、搬运（Carrier）、攀爬（Climber）、跳跃（Jumper）和推物（Pusher）任务上进行。每个候选机器人都先接受51.2万步的PPO控制训练，再进行仿真评分。

比较使用相同的评估预算和种群规模。基线为EvoGym标准遗传算法GA。Auto-Robotist的主要结果报告三个随机种子（0、9、42）下的均值与标准差，用于观察平均表现及运行间的波动。

实验从最终表现和搜索过程两个角度评价方法：

  • 最终找到的设计有多好。「最高奖励」指评估预算用尽时，搜索到的最优设计的任务得分。

  • 达到参考成绩需要多少次评估。「收敛加速S」是GA达到其最高得分所需的评估次数，除以Auto-Robotist达到同一得分所需的次数。S越大，表示所需评估越少；该指标按评估次数衡量搜索效率。

  • 搜索过程中有多大比例保持领先。「领先比例L」指在整个评估预算内，Auto-Robotist截至当时的最高得分严格高于GA的评估次数占比。

实验一：从零开始积累经验

第一组实验检验技能库能否在搜索过程中从零建立。Auto-Robotist从空白技能库出发，在5×5网格中设计机器人，并与相同评估预算下的GA比较。这就是文中的「冷启动搜索」。

表1｜5×5网格中的冷启动搜索结果

图3｜随评估次数增加，各方法截至当时的最高任务得分；上排为5×5冷启动，下排为10×10跨尺度实验（Auto-Robotist为三个随机种子的均值±标准差）

表1与图3显示，Auto-Robotist在七项任务上的平均最终最优得分均高于GA。按前述评估次数口径，平均收敛加速为1.66倍；平均领先比例为67%，即在各任务的搜索过程中，平均约三分之二的评估阶段保持领先。

搬运、跳跃和推物任务的最终得分提升较明显。这些任务对接触、承重与支撑结构较为敏感，设计经验可以帮助系统更有针对性地调整机器人身体。

图4｜搬运任务中的一个代表性设计演化过程

图4展示了搬运任务中一个机器人从初始设计到最终形态的演化过程。每一步修改都有技能库规则参与指导，任务得分从2.92提升到7.14，高于图中GA的6.40。这个例子让读者可以看到，设计经验如何参与一次次具体的结构修改。

实验二：在更大的设计空间中复用经验

第二组实验把5×5搜索中学到的技能库导入10×10网格，检验小网格中的设计经验能否帮助更大网格中的搜索。迁移时保留L1结构原型和L2设计规则，作为搜索起点的参考；原始L3观测不直接搬过去。新设计仍需重新训练控制器、接受仿真检验，并积累对应的评估记录。

表2｜10×10网格中的跨尺度结果（带参考设计的结果为三个随机种子的均值±标准差）

在同时提供技能库和5×5参考设计的设置中，Auto-Robotist在六项任务上超过GA，一项持平（表2）。按各任务原始奖励分数计算，最终最优得分的平均差值为+1.45。这说明，在本实验的更大设计空间中，已有经验能为搜索提供有效帮助。

图5｜10×10网格中代表性机器人的仿真运动过程

设计记忆有助于保留与任务表现密切相关的支撑和接触关系。图5对比了双方最优机器人的仿真运动过程。GA找到的部分机器人能够运动，却容易出现接触中断、支撑弯折，或将能量消耗在身体内部形变上的问题。

Auto-Robotist找到的代表性设计则更好地保留了稳定的行走框架、承重躯干，以及持续接触物体的推物结构。这些观察为性能差异提供了直观解释。


迁移的是设计规则还是具体外形

为了理解迁移为什么有效，研究团队做了两组对照：一组直接放大旧设计，另一组只提供设计规则而不提供旧机器人的外形（图6）。

直接放大外形，难以稳定保留原有性能。研究团队把5×5网格中的每个格子扩展成2×2小块，得到10×10机器人。虽然外形相似，接触、杠杆和载荷分布却发生了变化。例如，放大后的Auto-Robotist搬运设计得分仅为0.16。

这一结果说明，在这些任务中，直接放大不足以替代重新优化。设计规则的价值在于帮助新机器人重新组织支撑与接触关系，例如在驱动器周围布置支撑、为柔顺接触部位提供刚性支架。

不提供参考外形，设计规则仍能在部分任务上发挥作用。研究团队从提示中移除5×5参考设计，只保留技能库，结果在行走、搬运和跳跃任务上仍优于GA。这表明技能库包含可供新设计使用的功能性经验。

过桥、平衡和攀爬任务在同时提供参考设计时获益更多。对这些任务，规则说明应保留哪些结构关系，参考设计则提供一个具体的修改起点。

图6｜5×5与10×10网格中的代表性优胜设计（fit表示对应运行的任务得分）


哪些组件对效果有贡献

研究团队还逐个移除系统组件，观察性能如何变化。这类「消融实验」在行走和推物任务上进行，并采用相同的5×5冷启动协议，报告三个随机种子下的平均最优得分（图7）。

在推物任务上，移除GA随机变异通路后，得分下降24.0%；从提示中移除L2规则与L3观测后，下降23.8%；跳过规则修订（Diagnose）和重复条目合并（Merge），分别下降21.6%和14.0%。这些结果表明，探索新结构、使用已有经验和维护技能库都对该任务的表现有帮助。

行走任务中，对应下降为0.2%–4.3%。组件的作用随任务而变化，在结构搜索更困难的推物任务上更明显。

图7｜逐个移除组件后，行走与推物任务的表现变化（三个随机种子）


技能库到底记住了什么

研究团队检查了行走任务中形成的技能库。每条规则都能回查其对应的评估证据：读者可以查看它参考了哪些设计、这些设计得分如何，以及规则怎样参与后续设计。这让经验库可以被检查和修订。

图8｜行走任务中积累的设计经验，包括结构原型、正向规则与失败经验

如图8所示，技能库最终包含5个结构原型：底部桥式结构、门式框架、双脊框架、侧撑脊柱和锥形壳，以及12条正向规则与17条负向规则。五类原型都获得了采样权重，说明合并重复条目后，技能库仍保留了多种结构思路。

失败经验同样值得保留。在这个技能库中，负向规则甚至多于正向规则。脆弱的底部连接、过长的轨道、封闭外壳中的缝隙等反复出现的问题，都被记录下来，帮助后续设计避开已经发现的陷阱。


这项研究带来了什么

Auto-Robotist展示了让机器人设计经验持续积累的一种方法：

  • 为下一次设计留下知识。一次搜索的价值，还包括它能否留下可供后续问题使用的设计规则。

  • 让设计经验有据可查。规则关联具体评估记录，研究者可以检查、质疑并修订其中的内容。

  • 无需微调大语言模型，也能积累经验。LLM的参数保持固定，持续更新的是自然语言技能库；机器人控制器仍按任务通过PPO训练。

目前的验证集中在EvoGym的网格化软体机器人仿真任务。下一步可以探索三维结构与真实硬件设计，测试不同大语言模型下的效果，并完善规则的不确定性评估与冲突处理。这些设计经验能否经受真实硬件检验，仍需进一步验证。

每一次昂贵的仿真，都可以为下一次设计留下经验。当成功和失败都有据可查、能够复用，机器人设计搜索就成为一个持续积累知识的过程。

8. 开源版Super-agent降临，狂揽8万星！已跑通24小时全自动运营公司

11-06 18:57 原文链接

新智元报道

10 月 31 日，DeepSeek Harness 团队发表长文《Super-agent 设计探索》，迅速在 AI 圈刷屏。

文章讨论的是很多人都体会过的一种困境：Agent 越用越多，人反而越忙碌。

按照 DeepSeek 的观察，一个人通常只能同时跟进 3 到 5 个 Agent 会话——

单任务的上限取决于模型能力，多任务的上限取决于人的注意力。

他们设想的 Super-agent 长期在线、主动接活、能给其他 Agent 分派任务，人则退到决策和验收的位置。

双层架构：Router 层统一负责路由与对外交互，多个 Worker Session 隔离并发执行任务

文中还有一句颇具启发性的话：

相似的设计约束会导出相似的架构选择。

带着这句话，我们梳理了一遍已经上线的同类产品，最后找到了中国开源公司 LobeHub。

这家在 GitHub 上收获超过 8.4 万颗星的公司，过去大半年一直拿自己做实验，用自己开发的 Agent 平台组织自己的研发。

据创始人文彬介绍，团队已经三个月没在本地启动过开发服务器，看完 Agent 交来的验收报告就直接合并，开发速度提升了 3 到 5 倍。

与其转述这些说法，我们更想亲手验证一次，于是给 LobeHub 布置了一份夜班，让 Claude 和 ChatGPT 组成一个两人编辑部，每天早上给我们交一份量身定制的 AI 日报。

下面是这份日报从派活到交稿的完整经过，中间穿插着 LobeHub 团队里真实发生过的几件事。

前一晚｜给两位 AI 编辑派活

实测｜Part 1

我们在 LobeHub 里搭的编辑部一共三名成员，主管 Agent 负责派活和收稿，Claude 担任主笔，负责搜集素材、列大纲和撰写正文，ChatGPT 担任审稿人，负责指出逻辑和视角上的漏洞，最后再为文章生成封面和配图。

读者画像就照着我们自己来写，一位关注 Agent、基模、AI 商业化进展等话题的科技编辑，每天通勤时花五到八分钟，读完当天最值得关注的五到八件事，每条新闻都要有一手来源和一两句判断。

流程上，我们刻意把判断权留给主笔 Claude 老师。

GPT 可以提意见，Claude 也可以拒绝，只要讲得出理由，双方来回讨论，直到 GPT 表示无重大异议，或者满四轮为止。

整体上我们的设计思路是：

  1. Claude 负责搜集素材并撰写大纲->ChatGPT 提出修改意见
  2. Claude 参考意见，根据自己的判断自主决定是否要修改大纲、搜集新素材，形成意见，再交给 ChatGPT，二者辩论到收敛为一个统一意见
  3. Claude撰写初稿
  4. ChatGPT 给出修改意见，Claude 参考意见根据自己的判断自主决定是否要修改——这次不用辩论了，因为文字的可读性这块，Claude 比 GPT 强太多了，但前面撰稿思路这块可以帮忙补足视角和逻辑的不足
  5. Claude 修改完毕后，将文章交给 ChatGPT，在对应可插图的部分（包括封面）调用最强生图模型 GPT-Image-2.5-Sunburst（因为截稿前 LobeHub 还没上线对昨天刚刚发布的 GPT-Image-2.6 的支持）
  6. 交付稿件

类似这种不同模型多 Agent 协作的分工方式，LobeHub 自己的团队已经用了大半年。

他们研发群里的主管 Agent 名叫 Nasa，负责查看任务看板、分派工作和汇报进度。

早期执行 Agent 可以直接在群里发言，几个 Agent 轮番汇报，群里很快全是噪音，后来团队定下规矩，执行 Agent 只向主管汇报，由主管统一对外。

如今他们又加了一层，每个人配一个替自己过滤信息的 Personal Agent，人只听自己的 Personal Agent，活由各个项目的主管 Agent 去派。

主管 Agent 也不总是等人开口。

10 月 23 日晚上 8 点 24 分，创始人文彬在群里看到一张训练详情页的截图，随口评价了一句「这个 UI 一眼看上去还是太 vibe 了，得想想怎么 refine」，发图的同事随后去吃饭，55 分钟里没有人跟进。

9 点 19 分，一个设计 Agent 在巡查频道时判断这件事和自己有关，在没有被点名的情况下接手，指出页面上的进度信息重复了三遍、框里套着框、最显眼的位置却放着空值，当晚 11 点 52 分交出了改前改后的对比稿。

DeepSeek 设想的主动响应，也是先用规则过滤、再由模型判断是否介入，两者的思路非常接近。

凌晨｜两位编辑辩论到收敛

实测｜Part 2

主管 Agent 把任务分派下去以后，我们关掉电脑去睡觉，Claude 和 ChatGPT 的讨论在云端继续进行。

AI 和 AI 在深夜互相审稿，在 LobeHub 的代码仓库里已经是常态。

预训练走到后半段，喂给模型的数据大部分不是从网上扒的，而是让几个更早的模型先跑一遍生成的。点名的第一个，就是月之暗面的Kimi K3。

这叫什么？这叫Kimi给硅谷的明星实验室当了一回老师。

另一本账：用量翻倍，钱却没跟着涨

中国开源这么能打，闭源模型是不是该慌了？

故事远没这么简单。

如果只看使用量，开源的势头确实猛：token份额从11%升到19%，月处理量暴涨22.5倍，达到约2.9千万亿个。

但钱呢？支出份额反而从6%降到了4%。

原因很扎心：过去一年，开源阵营大多在卷同一件事——做更小、更快、更便宜的「flash」级模型，拼命打价格战。

价格战的结果就是：干的活多了一倍，收的钱反而少了——增量全被降价吃掉了。

打价格战的开源Flash模型们赢了吆喝，旗舰模型赢了钱包。

你设想一下：让AI修一个线上故障，读代码、查日志、定位问题、改文件、跑测试。便宜模型每走几步就跑偏，你得一遍遍解释、检查、返工，最后还是得自己上。Token账单是省了，工程师的整个下午搭进去了。

所以企业心里那本账，算的根本不是每百万token几块钱，而是这件事从头到尾干完，一共花了多少。模型调用费只是零头，人盯着、等着、改着，才是真正烧钱的地方。

便宜当然好，但得有个前提——活真能干下来。

不过话说回来，开源就干不了大活？

这已经不是「凑合能用」的水平，这是跟闭源旗舰掰手腕的水平。

开源差的，从来不是智商，而是企业对它的放心程度——合规、售后、长期路线，这些「考场之外」的分数，才是最后一关。
