2. 刚刚，Claude Haiku 5.5发布！价格暴降90%

10-08 07:24 原文链接

新智元报道

就在刚刚，Anthropic 发布了 Claude Haiku 5.5，单价只有上一代 Haiku 4.5 的 1/10、Sonnet 5.5 的 1/20，和 OpenAI 的 GPT-6 Luna 一个价。

官方跑分表里 Luna 交了成绩的六项全输给了它，好几项还咬住了 Sonnet。

  • 操作电脑的 OSWorld 从上一代的 15.7% 冲到 72.4%，离 Sonnet 5.5 只差 11.5 个百分点
  • 终端编程的 Terminal-Bench 4.0，上一代是零分，这次拿了 39.2%
  • 知识工作的 GDPval-AA 拿下 1620 分，是上一代的两倍多
  • 「人类最后的考试」HLE 不带工具，从 10.2% 涨到 45.9%
实际能省多少钱

价格是每百万 Token 输入 0.10 美元、输出 0.50 美元，这是提示在 10 万 Token 以内的价格，超过 10 万按输入 0.50 美元、输出 2.50 美元算。

缓存读取每百万 Token 0.01 美元，走批处理再打五折。

官方测算下来，同样的活平均比 Haiku 4.5 省 75% 左右，同样的预算大约能跑四倍的调用量。

没省到九成，是因为超过 10 万 Token 的请求只便宜一半，好在上一代 Haiku 约九成请求都在 10 万以内，另外新分词器会让同样一段话多出三成左右的 Token。

和 GPT-6 Luna 比，10 万 Token 以内两家的输入、输出、缓存价格完全一样。

面对长上下文时 Luna 更便宜，它要到 27 万 Token 左右才涨价，涨完也才输入 0.20 美元、输出 0.75 美元。

Sonnet 5.5 的缓存读取也从今天起砍半，每百万 Token 从 0.20 美元降到 0.10 美元，官方算下来多数 Agent 任务能便宜两成左右。

Max 和 Team 订阅本周起每月送 API 额度，Max 5x 送 100 美元、Max 20x 送 200 美元，Team 最多 500 美元、全队共用，在 Claude Platform 上哪个模型都能用。

跑分压过 Luna
但复杂编程还差 Sonnet 一截

这一代 Haiku 相比上一代，跑分进步巨大。

  • 操作电脑的 OSWorld 从上一代的 15.7% 冲到 72.4%，离 Sonnet 5.5 只差 11.5 个百分点
  • 终端编程的 Terminal-Bench 4.0，上一代一分没拿到，这次拿了 39.2%
  • 知识工作的 GDPval-AA 拿下 1620 分，是上一代的两倍多
  • 「人类最后的考试」HLE 不带工具，从 10.2% 涨到 45.9%

电脑操作是这次进步最猛的一项，OSWorld 上同价的 Luna 只有 48.9%，Haiku 5.5 甩开它 23.5 个百分点。

算上成本更夸张，它开到 Medium 档就超过了 Luna 满档的成绩，花的钱还更少。

知识工作的 GDPval-AA 上，Haiku 5.5 的 1620 分压过了 Luna 的 1437 分，离 Sonnet 5.5 的 1840 分还差一截，只开默认的 Medium 档也有 1277 分。

跑长线项目的 AA-Briefcase 上，它从上一代的 614 分涨到 1578 分，Luna 是 1336 分。

推理和读图上，HLE 带上搜索和代码工具时 Haiku 5.5 是 57.4%，Sonnet 5.5 是 64.5%。读专业图表的 Chartography，它从上一代的 6.4% 涨到 46.4%，Luna 是 29.1%，Sonnet 5.5 是 61.6%。

和 Sonnet 差距最大的是编程，Terminal-Bench 4.0 上它的 39.2% 是 Luna（16.4%）的两倍多，但 Sonnet 5.5 是 70.6%。

FrontierCode 上它的 46.4% 也赢了 Luna 的 42.4%，离 Sonnet 5.5 最好成绩的 52.1% 还差将近 6 个点。

官方也明说，复杂的 Agent 编程还是交给 Sonnet 5.5 和 Opus 5.5。

适合拿来干什么

官方给 Haiku 5.5 的定位是量大、要快、要省钱的活，比如写摘要、压缩上下文、查数据库、做分类。

它也是目前最快的 Claude 模型，只比开了快速模式（价格很贵！）的 Opus 慢，适合实时客服和浏览器操作。

官方也给出了一批明星 AI 应用公司内测反馈。

Asana 测下来，任务完成的延迟比他们现用的模型降了三成多，Box 测得它的延迟只有 Haiku 4.5 的一半左右。

另一个主要用法是给 Opus 或 Sonnet 当子Agent，大模型拆任务、拿主意，Haiku 分头去跑。

Cognition 的 Devin Fusion 让 Opus 5.5 当主力、Haiku 5.5 当副手，FrontierCode 稳在 66.2 分的顶级水平，成本和延迟都降了下来。

金融 AI 公司 Rogo 让大模型做 PPT，Haiku 5.5 钻进 10-K 财报扒分部营收数据。

Claude 开发者账号给出了 Demo，任务是用一堆家用杂物设计装鸡蛋的架子，目标是从 32 米扔下不碎。

Opus 5.5 单干用了 3 分 37 秒、试了 25 种方案、花了 0.47 美元，带上 10 个 Haiku 5.5 子 Agent 只用了 58 秒、试了 86 种、花了 0.14 美元。

Haiku 5.5 使用指南

Haiku 5.5 已经在 Claude 客户端、Claude Code 和 AWS、谷歌云、微软 Azure、Cursor、OpenRouter 等平台上线，模型 ID 是 claude-haiku-5-5，上下文 100 万 Token，单次最多输出 12.8 万 Token。

它是第一个能调思考档位的 Haiku，从 Low 到 Max 一共五档，API 默认是 Medium。

Python 和 TypeScript SDK 也加上了电脑操作和浏览器操作，目前是 Beta。

从 Haiku 4.5 迁移过来，同样的文字 Token 会多三成左右，max_tokens 和成本预估得重算。

budget_tokens 换成了自适应思考加 Effort 档位，temperature、top_p、top_k 要删掉，预填回复不能用了，格式要求改用结构化输出。

电脑操作要换成新工具集 computer_toolset_20260801，Priority Tier 暂不支持。

嫌麻烦可以在 Claude Code 里跑一句：

/claude-api migrate this project to claude-haiku-5-5

让它自己改。

当然，对于非开发者而言，你现在就可以直接在客户端里与 Haiku 5.5 对话了！

简单的问题就不要麻烦 Fable、Opus、Sonnet 了，Haiku 5.5 即使只是开 Low 档推理强度，也可以做到准确地秒出答案，完美替代搜索引擎了。

快去试试吧！

1. Claude打通谷歌办公三件套！文档表格PPT直接改

10-08 07:24 原文链接

新智元报道

AI生成内容越来越快，你要收尾的活儿却越攒越多。

改个开头，换个思路，AI很快就能给你生成新方案。可每多一个版本，你都得重新复制、排版、核对。

粘回文档，段落散了、格式丢了；数字一变，表格得跟着调整；PPT里还留着旧内容，你又得一页页替换。

往往AI已经开始写下一版，你还在给上一版收尾。

这种给AI当「搬运工」的日子，就要终结了。

10月6日，Anthropic宣布，Claude接入Google Docs、Sheets和Slides，向全部付费计划（Pro、Max、Team和Enterprise）开放公开Beta。

安装插件并授权后，你可以直接在Google文档、表格和幻灯片的侧边栏里，让Claude改稿、修公式、补页面，修改就直接落在当前文件里。

当然，你也可以从Claude聊天窗口开始。

启用对应的Google连接器并完成授权后，把已有文件的链接贴进对话，就能让Claude打开并修改。

如果还没有文件，也可以直接让它新建一份Google文档、表格或幻灯片。

官方还挑选了三种常见的办公苦差事，分别展示了Claude在这三个应用里的操作：

在Docs里，把密密麻麻的方案理出重点；在Sheets里，对照预算与实际支出，找出哪里花超了；在Slides里，把客户资料和沟通记录做成一套季度汇报。

结果就是，Claude直接在你的文件里干活，改好的内容也留在原处，让你少做几次复制粘贴，少折腾几遍排版。

改文档：对着原稿，直接动手

一份方案写得很满，读起来却抓不住重点，这种情况太常见了。

演示中，用户让Claude做几件事：精简摘要，把建议放到前面，统一标题样式，再把下一步事项整理成表格。

原本挤在一起的文字，变成了有层次的方案：建议被突出，关键数字单独呈现，任务也按负责人、时间节点等信息重新组织。

Claude在原文档里精简摘要、调整格式，并将下一步事项整理成表格。

这些修改就在Docs里完成。原稿不用先搬出去，新版本也不用再粘回来，改完直接对着原文件检查。

如果只想处理某一段，可以选中文字，让Claude局部改写。

按官方介绍，它支持调整标题样式、保留周围格式；较大幅度的重写，也可以先给出修改卡片，由你决定接受还是放弃。

改文字、理结构，都留在同一份文件里。少搬一次内容，思路也少被打断一次。

做表格：两份数据，直接整理成报告

表格最磨人的地方，往往是数据到手了，离能用还差一大截。

预算一份，实际支出一份。要对账，还得合并数据、分组汇总、拉图表，再找出哪里花超了。

演示中，用户把预算和实际支出两份CSV拖进Sheets侧边栏，要求Claude按团队分别建立工作表，再生成带图表的汇总页，标出超预算项。

整理好的数据和分析结果，直接写进当前表格：各团队的数据分到了不同工作表，汇总页把预算、实际支出和差额摆在一起，哪些项目花超了，也一眼能看出来。

Claude对照预算与实际支出，按团队生成工作表，并在汇总页标出超预算项。

分析完，文件就在手边，中间少了一趟搬运。

除了这种报告整理，Claude还能读取当前表格和选中的单元格，帮助编写、修正公式，清理日期等数据格式，构建数据透视表和原生图表。

遇到复杂的数据合并、清洗，它也可以把一个区域的数据交给Python处理，再将结果写回原表。

不过，报告有了不等于账就对了。

公式、汇总口径、异常项仍要核对，尤其是后面要拿这些数字做汇报时，该查的账不能省。

做PPT：资料交给AI，直接生成汇报

临时要做汇报，常见流程是：让AI写内容，自己塞进模板，再挨个调字号、颜色和位置。

演示中，用户在Slides侧边栏启用相关连接器，让Claude结合Salesforce里的客户资料和Google Drive中的近期沟通记录，生成一套季度客户汇报。

空白演示文稿随后出现了多页内容：摘要、使用情况、目标进展、客户诉求和下一步计划，都被组织进同一套幻灯片。

Claude结合已连接的客户资料和沟通记录，直接在Google Slides里生成季度汇报。

这也说明，侧边栏可以借助已启用、已授权的连接器读取其他资料，再把结果写进当前文件。

如果手头已经有一套PPT，Claude也可以根据当前Slides的主题和布局补新页面，让新增内容匹配原有风格。

某一页文字太挤，它可以尝试拆成两页，它还能检查元素重叠、内容跑出页面、文字难以阅读等问题。

这些零碎的活儿有AI帮着做，准备汇报就能省不少事，才有空看看内容本身讲得清不清楚。

边聊边改文件就放在对话旁边

如果连草稿都没有，或者想先把需求聊明白，可以从Claude聊天开始。

启用Google Docs、Sheets、Slides对应连接器并完成授权后，把已有文件链接贴进去，Claude就能操作你有权限访问的文件。也可以直接说：「帮我新建一份Google文档。」

在支持的环境中，文件会在对话旁边打开。你可以边聊边看，也可以自己修改，Claude继续在同一份文件里编辑。

并排窗口目前支持Chrome网页端，以及开启内置浏览器的Claude桌面端。文件访问仍受原有Google共享权限约束。

这里有个小细节：要明确说Google文档、表格或幻灯片。只说「做个文档」，它可能生成一份可下载的文件。

两个入口的功能也不完全一样。

聊天中的Docs连接器能读取评论和建议，文件侧边栏目前不能读取评论，也不能接受或拒绝已有建议。聊天中的Slides连接器目前还不能添加图表，修改也可能不会实时显示在并排窗口里。

对着现成文件改，可以用侧边栏；从资料和需求开始做，可以先从聊天进入。

AI能动手用户怎么把关？

让AI直接改原文件，改错了怎么办？

Claude侧边栏默认采用「修改前询问」模式：先说明准备做什么，等你批准后再执行。也可以开启「接受全部修改」，让它连续完成普通内容编辑，少停下来问几次。

Claude在Docs侧边栏展示修改建议，用户审阅后再应用。

不过，添加外部链接、从网址插入图片等操作，仍然需要单独批准。

修改会以你的用户名记录在Google文件版本历史里。改得不合适，可以撤销，也可以恢复到之前的版本。

这次Beta覆盖Pro、Max、Team和Enterprise。用户需要安装插件、完成授权并登录Claude；使用组织账号时，能否安装插件还取决于Google管理员的设置。

侧边栏处理的是当前打开的文件。关掉侧边栏，当前任务就会停止，也不能自动把任务交给另一个应用接力完成。

Slides里的图表还有一个容易踩坑的地方：Claude通过侧边栏新增的图表是图片，不会随着Sheets中的数字变化自动更新，需要重新生成。

所以，表格里的数字改了，汇报里的图表还得跟着检查，别拿着旧图讲新数据。

省没省时间，还得算上检查和返工。少点几次确认，却多花半天改错，那就未必划算了。

AI办公一边竞争，一边打通

看到这里，很容易想到OpenAI近期推出的Space和Pages。

OpenAI围绕ChatGPT搭建新的协作空间，把资料、讨论和创作放到一起；Claude这次则走进用户已有的谷歌办公文件，直接在熟悉的文档、表格和幻灯片里打下手。

有意思的是，这场竞争，也不是各家关起门来各干各的。

微软的Microsoft 365 Copilot，既接入OpenAI的模型，也引入Anthropic的Claude。

OpenAI一边建设自己的办公入口，一边为微软的产品提供模型；Claude则同时进入微软和谷歌的办公环境。

大家争的是用户每天从哪里开始工作，合作解决的，则是AI怎样进入这些工作。

谷歌最近还补上了另一块拼图：让Markdown文件直接在Drive和Docs里使用。

Google Workspace工程副总裁Chandu Thota在X上表示，Markdown已经成为人和AI智能体之间的「共同语言」。

从规格说明、工作计划到任务清单，甚至AI生成的文档，很多一开始就是.md文件。

现在，这些文件不用先转成Google文档，就能直接打开、编辑、评论，并与其他人一起协作。

Google开始支持直接编辑Markdown文件，无需转换格式，也能评论和多人协作。

Thota看重的，正是那些不起眼却磨人的麻烦：反复导入导出，转换之后格式乱了，讨论同一份内容还得在几个工具之间来回折腾。

网友已经开始催下一个功能了。

Chirag Nagpal就在评论区追问，能不能也支持正文里的LaTeX数学公式？

文字、表格能接住了，Markdown里的数学公式，能不能也直接识别、正常显示，少让用户折腾一轮格式？

模型正在进入办公软件，办公软件也开始接住AI常用的文件格式。人和AI对着同一份文件接着干，中间的搬运和转换就有机会少一些。

对普通用户来说，谁和谁合作，并没有那么重要。

大家更在意的是能不能少搬几次内容，少调几遍格式，少返工几次。

这些杂活能省下多少，才决定了AI办公究竟能让我们轻松多少。
