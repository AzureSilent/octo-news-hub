2. 全新OpenClaw 2.0发布：龙虾史上最大更新，已无人关心

09-01 07:31 原文链接

新智元报道

OpenClaw 2.0 来了。

933 个贡献者，16000 个 PR，占项目历史合并总量的一半。此前 230 天发了 106 个版本的项目，忽然七周没出声。

社区已经在写讣告的时候，它推出了项目历史上最大的一次更新。

这份成绩单放在 3 月的话，成果令人炫目。放在 8 月底，只让人叹气。

该走的人已经差不多走光了。留下的养虾人不需要 2.0 也会留着。

龙虾死于经济学

OpenClaw 的 250K 星爆发建立在一个漏洞上。

这个漏洞叫「用 20 美元的 Claude Pro 订阅跑价值几千美元的 Token」。

OpenClaw 的早期用户画像极度统一：拿着 Anthropic 的包月订阅，通过 OAuth 搭车，让龙虾 24 小时替自己烧 Token。

部分用户用 200 美元的 Claude Max 订阅干出了 1000 到 5000 美元的 API 用量。

2026 年 4 月 4 日，Anthropic 堵上了这个口子。

第三方工具不再允许搭载 Claude 订阅的 OAuth。

拓展阅读：一夜翻脸，Anthropic正式封杀OpenClaw！全球开发者24小时血崩

用户要继续用龙虾跑 Claude，得按 API 价格付费：Sonnet 4.6 每百万输入 token 3 美元，Opus 4.6 每百万输入 15 美元。

一夜之间，部分用户的月账单涨了 50 倍。

补贴一收回，增长曲线立刻反转——和每一次互联网烧钱大战的退潮一模一样。

创始人 Peter Steinberger 2 月就去了 OpenAI，项目交给基金会。

拓展阅读：突发！OpenClaw创始人加入OpenAI：智能体革命，真的来了

安全问题随后集中爆发：Snyk 审计发现 36% 的 ClawHub 技能含提示词注入攻击，Palo Alto Networks 的 Unit 42 在 2 月到 5 月之间持续发现未被拦截的恶意技能。

「OpenClaw 已死」 逐渐开始成为全球科技媒体的流量密码。

Harness 时代：一鲸落万物生

2026 年 Agent 行业最热的词，是 Harness。

这个词的含义是：包在大模型外面的那一层工具调度、权限管理、会话记忆和执行沙箱等——简单来说，除了模型以外的部分都是 Harness。

Firecrawl 7 月的横评文章开篇第一句话就是「前沿模型已经趋同，Agent 的体验由 Harness 决定」。

https://www.firecrawl.dev/blog/best-ai-coding-agents

Claude Code、Codex、Cursor、OpenCode 等等这些 2026 年叫得上名字的编程 Agent，每一个都是这个架构。

模型负责判断，Harness 负责工具、权限、并发、断点恢复和上下文管理。

这个架构，龙虾 1 月份就跑通了。

OpenClaw 的 Gateway 做的事情和今天所有 Harness 做的事情高度重合：接收指令、调度工具、管理凭证、维持会话、跨平台路由。

谷歌工程师 Addy Osmani 对此的观察是：这些 Harness 彼此之间的相似度，远高于它们各自底层模型之间的相似度。

https://addyosmani.com/blog/agent-harness-engineering/

Linux 基金会 2026 年成立了 Agentic AI Foundation，接受了三个东西：Anthropic 的 MCP 协议、OpenAI 的 AGENTS.md 规范、以及 Goose 项目。

MCP 解决工具发现，AGENTS.md 解决指令规范，Goose 解决执行运行时。

三块拼图合在一起，就是一个标准化的 OpenClaw。

https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation

龙虾没赢，但赛道本身就是龙虾画出来的。

它像 VisiCalc（你不知道很正常）——第一个让所有人看见「电子表格」这件事能成立的产品。最后赢的是 Lotus 1-2-3（你不知道也很正常），再后来才是微软 Excel。

定义赛道的和赢得赛道的，往往并非同一个玩家。

OpenClaw 在中国水土不服

龙虾的核心卖点只有一句话：在你已经在用的聊天软件里指挥 AI 干活。

这个思路，飞书 CLI 做得更干净。

2026 年 3 月 28 日，飞书开源了官方 CLI 工具，GitHub 仓库 larksuite/cli，MIT 协议。

覆盖即时消息、云文档、多维表格、日历、视频会议、邮箱、任务、知识库等 11 个业务域，200 多条命令，23 个 Agent Skills。

npm 全局安装后两行命令接入 Claude Code，开源不到两个月拿了 8000 多颗星。

它跟 OpenClaw 的主要区别在三个层面。

第一，飞书 CLI 是嵌入式工具，Agent 通过 CLI 调用飞书的能力，权限跟着企业管控走；

OpenClaw 是接管式框架，要求用户把整台电脑的文件系统和聊天账号都交给 AI，24 小时在线。

第二，飞书 CLI 背后是飞书开放平台的 2500 多个 API，鉴权、审计、权限回收都有现成的企业级基础设施；

OpenClaw 的安全审计在 Palo Alto 发 CVE 之后才开始匆忙补课。

第三，对于中国用户来说，飞书是每天打开时长仅次于微信的办公工具；

Discord 和 Telegram 是龙虾的主场，不是中国用户的主场。

企业 Agent 的起点是上下文。

飞书的 IM、文档、知识库、审批流本身就是上下文网络，Agent 应该在这个网络里工作，而不是从零搭一个新的。

这正好是 OpenClaw 做不到的事。

龙虾给了用户一个空框架，让用户自己去接 API、配权限、管安全。

飞书 CLI 直接把框架预装在了用户已有的工作系统里。

2.0 改了什么，已经无人关心了

回到 OpenClaw 2.0 本身。

  • 安装简化了，扫描机器上已有的 Claude 订阅、API 密钥和本地模型，自动配置，缩短从安装到第一次对话的时间。
  • 浏览器端重做了，Control UI 启动时间从 1.6 秒降到 575 毫秒，JS 请求从 140 个砍到 45 个。
  • 安全性增强了，外部插件安装需要验证来源，ClawHub 展示安全审计信息，凭证请求不再进入聊天上下文和模型输入。
  • 共享云会话是唯一的新能力——团队可以把一个正在跑的任务连同上下文交给另一个人。

每一项都该做，可惜做晚了。晚了太多太多。

这些修复回答的问题是「用户为什么装不上」和「用户为什么不敢用」。

没有回答的问题是：用户装完第二周为什么不打开它。

编程 Agent 的生产力回报是可见的，代码就摆在那里，跑得飞快。

OpenClaw 式的「生活助理」跑完一天，回头看聊天记录，龙虾帮你转发了三封邮件、总结了一条新闻。

省下来的时间，不够配置它花的时间。

Hermes Agent 指出了一条可能的出路：自学习循环，用越久越聪明，任务完成后自动把经验沉淀成可复用的技能。

OpenClaw 2.0 默认开启了 Skill Workshop 自动学习功能，方向是相同的，但刚起步，实际效果有待检验。

Hermes 在 OpenClaw 退潮期间悄悄涨到了 24 万星，OpenRouter 上的日均 Token 消耗量排到了全局第一。

https://openrouter.ai/apps/hermes-agent

OpenClaw 2.0 是一次工程大补课。

569 个新贡献者进来干活，团队没有摆烂。这值得尊重。

但产品层面，龙虾的窗口期已经关了。

编程场景被 Claude Code 和 Codex 吃掉，中国办公场景被飞书 CLI 接管，「后端 All in One」的架构思路被 OpenCode 等 20 万星的开源 Harness 继承。

龙虾每一块肉都被分走了，只剩下壳了。

一鲸落，万物生。

OpenClaw 对 2026 年 Agent 行业的贡献，在于它的经历。

它用九个月告诉所有人三件事：Agent 的界面是聊天窗口，Agent 的价值在 Harness 而非模型本身，Agent 的安全不能事后再补。

每一个后来者的第一版架构文档里，都能看到这三条教训的影响。

而龙虾，恐怕再难重演今年 3 月全民养虾的巅峰时刻了。

1. AI写得太快，人类审不动了！OpenClaw断更7周，一版吞下1.6万个PR

09-01 07:31 原文链接

新智元报道

OpenClaw，整整憋了7周。

这个GitHub历史上增长最快的开源项目，此前230天发了106个版本，平均两天多就甩出一版。

这次，正式版硬是断更了近7周。

而且，这次2.0版本的诞生，还是意外才得来的。

8月30日，OpenClaw发了一篇博客，标题就叫《OpenClaw 2.0, Accidentally》（意外做出来的2.0）。

31日凌晨，v2026.8.1刚刚正式挂上GitHub。

一边叫2.0，一边叫v2026.8.1，其实是同一个版本。「2.0」只是个宣传名，仓库里用的仍然是按日历走的版本号。

官方称，这一版由933名贡献者完成，其中569人是第一次参与这个项目，共纳入超过1.6万个PR。

更让人震撼的是后面的数字：这些PR数量，大约占了OpenClaw历史上全部已合并PR的一半。

也就是说，这个项目「大半辈子」的代码，被压进了这一次的版本里。

作为对照，上一个正式版v2026.7.1发布于7月13日，官方记录是3063项贡献、532名贡献者。

一个半月过去，贡献者数量翻了近一倍，PR体量更是直接涨了一个数量级。

官方给的理由倒也算合理：

一版塞了半部项目史，宁可多花时间让新老用户都能顺利装上，也不想急着发出去，再甩给大家一堆坏掉的配置。

慢下来是因为活太多了

按官方说法，慢下来不是没活干，相反，是活太多了。

团队在变大，工作的体量和节奏，已经超出了OpenClaw原有底层架构和发版流程能扛的范围。

于是，这次干脆两件事一起返工：底座重做一遍，发版流程也重做一遍。

两次正式发行之间隔了约48天。

中间并非完全停摆，beta等预发布版本一直在走，只是稳定版一直没出来。

这次更新，最初的目标其实很小：

只想把安装流程简化一点，把浏览器端重做成第一入口。

没想到，一路清理下去，收不住了。

消息、记忆、Skills、模型、自动化、插件、安全、原生App，几乎每个模块都被翻了一遍，最后变成了他们口中的「2.0」。

PR有了新名字prompt request

比1.6万这个数字更值得琢磨的，是这些PR是怎么来的。

就在新版发布前几天，GitHub官方采访了OpenClaw的一批维护者。

项目创始人Peter Steinberger说了一句：

我甚至不管它们叫pull request，我管它们叫prompt request。

另一位维护者说得更直白：有人干脆架了一条自动化的「软件流水线」，一口气挂几百个PR，把整个仓库的毛病挖了个遍。

截至8月26日，OpenClaw已经积累约38.8万Stars、8.1万Fork、超过8万次提交。

而这个项目2025年11月才起步，最初只是Peter Steinberger的一个周末小玩具。

十个月，这么多人涌进来，麻烦也跟着来了。

代码能批量生产之后，PR数量就不再说明任何问题。

一个人提300个PR，可能是真解决了300个毛病，也可能是让智能体把仓库扫了一遍、批量交上来碰运气。

维护者从PR列表上看不出区别，于是干脆换掉了「信任信号」。

现在他们更想看的是：你和智能体的对话记录、跑过的测试、截图，以及你能不能说清楚这个改动为什么这么改。

Peter Steinberger的原话是：

没人在乎代码是不是你写的，但我们在乎你有没有真的想过这个功能。

维护者开始用AI审AI

审代码的方式，也跟着变了。

有维护者收到AI写的PR，直接点一下Copilot审一遍，看清楚改了哪些文件、各自是什么意思。

还有人干脆不打回重来，收到PR就自己上手改到对。

有意思的是，门槛抬高了，门却没关上。

维护者说，首次被合并的PR里，有相当比例来自没有开发背景的人。

他们只是碰上一个具体问题，让智能体写了个补丁，再跟维护者一起改到能合并为止。

更麻烦的是，连「合并数」，这种老指标都被污染了。

有人直接复制别人的PR，就为了刷合并次数，攒出一个看起来可信的贡献者形象。

于是，出现了一个略显荒诞的局面：AI把代码产能拉满，人的评审、架构和发布流程，反而成了整条链路上的瓶颈。

从极客玩具到多人接力

产品这条线上，OpenClaw这次明显在往普通用户那边转向。

首次安装，不再逼你先配一堆东西。

它会先看你电脑里已经有什么：已登录的ChatGPT或Claude、手上的API Key、本地跑着的模型，能接上的直接接上。

大量配置被挪出安装流程，你可以先聊起来，剩下的设置边聊边补。

浏览器端，被重做成第一入口，多数人第一次见到自己的Claw就在这里。

翻发行说明，还能看到一堆很「日常」的东西：

按关键词搜过去的对话、任务进度卡刷新后还在、把交互组件钉到会话面板上、让智能体单独找你要一次凭据，而不是把它甩进聊天记录里。

官方举的例子也足够生活化：让你的Claw盯着邮箱，孩子学校一有作业或活动通知，就给你发一条Telegram。

另一个变化更值得注意：它开始变成多人的了。

官方说，团队自己造这一版时，越来越多的活是丢给各自的Claw干的，然后就撞上一个问题：想把同事拉进来一起弄，Claw之前知道的那些上下文就没了。

共享云端会话，解决了这件事。

一个人起的任务，别人可以进来看，也可以直接接手，上下文照旧留着。

任务还能挪到配对的设备或云端机器上跑，人合上电脑，活继续。

一个任务在群里被三个人轮流接手，Claw始终记得前面发生过什么：这大概就是「个人智能体」这个词开始松动的时刻。

不过，官方在发行说明里写得很清楚，这套团队角色属于协作控制，并非给互相敌对的租户做的安全隔离。

不能当企业级多租户来用。

想要升级？这几个坑先避开

这不是一次无痛更新。

正式发行说明里，还挂着两项标着breaking的改动，意思就是升完级东西可能就不好使了。

一个是内置的OpenProse插件被整个拿掉了，以前的/prose命令没了。

另一个是OpenAI和Codex的模型名改了，你配置里写的旧名字全部失效，得跑一遍openclaw doctor --fix让它自动改过来。

装了第三方插件的还要多留一步。

官方给插件开发者划了条线，9月1日之后，一批老的接口就不认了。插件作者要是没跟上，你这边可能就直接用不了。

原生App这边，macOS的签名和公证版本已经可以下载，iOS和Android的新版分发另外跟进，别指望一起到位。

安全这块也没有标准答案。

维护者做过一次收紧，规定Claw只能在你指定的文件夹里干活。结果不少人早就用软链接把别的目录挂了进来，一收紧全断了，投诉立刻涌过来。

可要是不管，安全报告又会把他们淹掉。

Peter Steinberger的说法是，在「用着顺手」和「默认够安全」之间找平衡，是场很难打的仗。

发版这块，团队现在分了四条道：stable是普通用户的正式版，extended-stable是上个月版本的维护线，beta是预发布，dev则跟着主干实时走。

新东西先进beta跑，验证没问题才进stable，想尝鲜的走beta，只想安稳用的守着stable。

这更像是把「高速开发」和「稳妥发布」拆到两条轨道上，各跑各的，互不耽误。

回头看这7周，真正有意思的地方并不在功能列表。

过去，大家担心的是AI写不出能用的代码。

现在，这个增长最快的开源项目给出了另一种答案——代码多到人看不过来，才是下一个瓶颈。

OpenClaw憋了7周才交出一个2.0，不是它慢了，是人类还没跟上AI写代码的速度。
