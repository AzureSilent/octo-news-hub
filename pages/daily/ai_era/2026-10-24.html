7. 突发，Claude Code灵魂人物Thariq Shihipar宣布离职！

10-24 14:48 原文链接

新智元报道

就在刚刚，Claude Code核心作者正式离职Anthropic！

Thariq Shihipar是Claude Code团队的核心灵魂人物、被开发者社区尊称为「解释之王」。

他在X上正式发布了一封长文告别信。

在短短45分钟，Claude团队最知名的两位成员相继离职。

到底发生了什么？

体面的告别信：什么是真正的「向上竞赛」？

「在加入Claude Code 一年多，并亲眼见证它的规模扩展到远超我曾经的想象之后，我离开了 Anthropic。」

在告别信开篇，Thariq这样写道。

作为陪伴 Claude Code 从有争议的新工具到「无数开发者默认编码方式」的核心推手，他在最巅峰时刻，选择了离开。

紧接着，他抛出了整封信最核心的价值观：「向上竞赛」。

我真的非常热爱在 Anthropic的工作，深度认同公司的使命。最重要的是，我坚信『向上竞赛』的理念。如果我们努力且负责任地工作，我们就能抬高行业的标准，并激发其他人走向更好的结果。如果我们都能互相推着对方变得更好，事情就会变得极其美好。我将永远带着这种精神前行。

在大模型疯狂内卷的今天，Thariq 犹如一股清流。他眼里的AI竞赛，不是零和博弈，而是一场提高全人类标准、倒逼彼此变得更卓越的事业。

对于同事们，他给予了赞美——

「我在 Anthropic 的同事们，是我一生中遇到过最有才华、最周到、最能干且最真诚的人。我很高兴现在是他们在掌舵，我深深地信任他们。」

在信的结尾，他将聚光灯交还给了团队，一口气@了多位 Anthropic 的核心开发者，呼吁大家继续关注他们。

虽然告别信十分官方，但Thariq在评论区，还是发出了一个亮点评论：「等等，是不是只有我一个人觉得 Opus 5.5 变蠢了？」

从MIT天才、YC明星创业者到AI先锋

Thariq的履历，仿佛开了挂。

他不只是传统研究员，而是一个横跨学术界、顶级大厂与硅谷创投圈的「六边形战士」。

早在多伦多大学攻读工程科学本科期间，他就展露出了极强的产品直觉，联合创办了聚合消息通知的插件 Chime，并在2013年直接被 HubSpot 收购。

随后，他进入科技极客的梦想圣地——MIT Media Lab深造，并担任研究科学家。

在那里，他联合主导了颠覆传统PDF的交互式学术出版平台 PubPub，试图用动态程序重塑人类知识的展现形式。

随后，带着对复杂交互的深刻理解，Thariq 一头扎进创业赛道。

他创办了浏览器端游戏创作平台 One More Multiverse，不仅成功杀入全球顶尖孵化器YC，更是一手将平台做到了百万级用户规模。

这款灵感来自跑团和Roblox的产品，斩获了超1700万美元的融资。

直到2025年，在经历了一段专注AI可解释性研究的Fellowship沉淀后，这位CEO，选择以「技术人员」的身份加入 Anthropic。

可以看出，Thariq 的每一步都在解决同一个核心问题：如何让极度复杂的系统，变成普通人一眼就能看懂、上手就能用的绝佳体验？

正是这种「游戏CEO」与「MIT学者」的双重视角，让他在加入 Claude Code 团队后，敏锐地察觉到了当前AI开发的盲点——不要再执迷于给模型无脑堆算力了，应该重塑的，是人类与AI的交互。

巅峰隐退背后：他留给AI行业的4条真相

作为前 YC 明星创业者、MIT Media Lab 的研究员，Thariq 带着极强的产品直觉改造了 Claude Code。

此前，他曾输出以下观点。

真相一：大模型的智力已经「过剩」，算力不再是第一瓶颈

Thariq 曾尖锐地指出：现在的强模型（如 Opus 5）其实已经非常聪明了，真正的瓶颈根本不是原始算力，而是交互接口与人类自身的理解力！

能力冗余，是指一个模型在配备合适的智能体运行框架（Harness）、获得环境访问权限和代码执行能力后，能够完成的任务，远远超出了它仅靠普通对话、缺乏外部工具支持时所展现出的能力。

真相二：强模型时代，请勇敢砍掉80%的提示词！

Thariq 团队在内部实验中，对强模型直接砍掉了超80%的系统提示词，结果发现代码能力根本没有下降！

链接：https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/

他主张：过度约束反而会限制更强模型的发挥。把规则做成按需调用的模块化「Skills」，给AI留出自由发挥的空间。

真相三：告别 Markdown，HTML 才是高密度交互的未来

程序员最爱的 Markdown，正在成为人机协作的阻碍。当 AI 输出的代码和计划越来越长，人类往往会因为阅读疲劳而「盲目点击同意」。

Thariq 断言，带图表、带颜色差异比对、可交互的 HTML 界面，才是未来能让人类真正保持判断力的交互方式。

真相四：未来人类的终极职业——「算力分配者」

别怕AI写代码比你快。

在未来，你的角色将变成「计算资源分配者」。你的核心价值在于：决定把昂贵的 Agent 算力投入到哪个方向，并在关键节点利用主动提问工具（如 AskUserQuestion）消除盲点，时刻把控方向盘。

或许，Thariq Shihipar已经找到「向上竞赛」的方向，准备好下一个创业方向了？

6. 刚刚，Claude不聊天了！一句话出看板、出动画，直接交成品

10-24 14:48 原文链接

新智元报道

Claude大更新：动态看板、动画、PPT一起上！

刚刚，Anthropic一口气官宣了三件事：实时仪表盘Dashboards上线，代码动画Motion上线，文档Docs、幻灯片Slides、设计Design三件套摘掉beta标签——免费用户也能用。

上个月底，OpenAI刚在DevDay上高调推出ChatGPT Space，一个让Agent和同事在里面协作、维护动态图表和文档的项目中心。前后不到10天，Claude就把仪表盘和动画端上了桌。

X评论区已经炸了。

有人说「我200美元的Max套餐每天都在增值」，有人直接喊「根本跟不上你们的节奏」。

还有开发者追问：Dashboards什么时候开放API，让我在自己的应用里实时生成看板？

这个追问很说明问题。用户已经不满足于让AI出主意了，大家默认它该交成品。

Anthropic这次一共动了三样东西。

Docs、Slides、Design结束beta，所有计划都能用，包括免费版。自从这三样塞进每个对话以来，用户已经在Claude里做了超过4500万份文档、演示文稿和设计。

但新来的两个就没这么大方了。Dashboards还在beta，只对付费计划开放。Motion也在beta，门槛更高，只给Team和Enterprise两档企业用户。

所以免费用户拿到的是文档、幻灯片、设计三件套的正式版。想玩仪表盘和动画？得付费。

仪表盘：治的是「等」

在公司里想知道一个数值，你通常只有两条路。

要么提工单，排在数据同事的待办清单后面慢慢等。要么自己去学SQL——就是从数据库里捞数据的那种专门语言，对着一堆表名发呆。

大多数人的选择很现实：等，或者干脆不看了。

Dashboards把这一步省了。

把Claude接上公司的数据平台（BigQuery、Snowflake、Databricks这些可以理解成存放全公司业务数据的大仓库），然后用大白话问一句「这周注册量和上个月比怎么样」。

Claude自己写查询、自己取数、自己搭看板。数据变了，看板跟着变。

接上Salesforce这样的CRM工具，还能给销售商机单独搭一块板。

但真正的卖点不是「会画图」，而是「看得见」。

点任何一个数字，背后那段查询就摊在你眼前。看不懂？让Claude解释。每张图都标着数据最后一次刷新的时间。

动画：做视频却一帧画面都不生成

数据看清了，下一步是讲给别人听。

Motion管的就是这一段。

你可以让它把季度报告做成全员大会上30秒的讲解动画，给董事会PPT里的图表加动效，或者做一段给客户看的产品上手演示。

做完在编辑器里调，或者直接让Claude改，最后导出MP4。

一个做视频的功能，却一帧画面都不靠视频生成模型。

Claude写的是代码。文字怎么飞进来、图表怎么长出来、形状怎么变化，全写在代码里。

这个设计对汇报场景太关键了。汇报最怕的就是数字错。用生成模型做视频，一个数字错了只能整段重抽，抽出来别处可能又变了。

代码驱动的动画不一样，任何一个字、一个数字、一个时间点都能单独改。

说到做视频，Opus 5.5已经让人坐不住了

其实在Motion正式上线之前，Opus 5.5的代码动画能力已经在社交媒体上杀疯了。

Opus 5.5发布后，X的时间线迅速被各种动效短片淹没。

有人花15秒做了一段点餐发布片，一镜到底、无模板、纯代码。

更夸张的是，有人让Opus 5.5做了一个「Claude放假」的动画短片，拿下5.7万播放和1300多个赞。

别忘了，这些统统不是视频生成模型的产物。

但这恰恰说明了一件事——代码驱动动画的天花板，比大多数人想象得高得多。

Motion把这条路铺进了产品里，普通人不用折腾命令行，在对话框里说一句就行。

说点实在的。

模型之间的差距，普通人越来越难感觉到。

但少提一张工单、少熬一晚PPT，谁都感觉得到。

以前的分工是人干活，AI帮忙想。现在顺序倒过来了，AI先交第一版，人的价值挪到了判断这东西能不能发出去。

官方那句话说得很准：Claude做第一版，你决定分享什么。

这次更新还把协作那一步补上了。

团队成员和Claude可以同时编辑同一份文档、演示或看板。管理员允许的话，做好的东西还能分享给公司外的人。

导出的PowerPoint和PDF跟编辑器里看到的一模一样，演示文稿还能直接进Google Slides当可编辑文件。手机App上也能改。

双雄挤进同一张办公桌

OpenAI的ChatGPT Space面向Pro、Business、Enterprise用户，页面里放动态图表、协作文档和清单，能从连接的数据源自动更新，还能@同事和自家的Agent Dots去办事。

Claude这边是仪表盘、动画、文档、幻灯片、设计全家桶。

两家几乎同时盯上了同一块地方：打工人每天的那张办公桌。

以前大家盯着谁的模型分数高，现在要看谁先成为打工人每天第一个打开的窗口。

长期看，用户从哪个窗口开始干活，话语权就在谁手里。等大家习惯了先在对话框里要一个初稿，专业软件就慢慢变成了Claude后面的那道工序。

工作产出的最后一公里，就是从「答案」到「能直接发出去的东西」之间那段路。谁把这段路铺平，谁就赢下办公桌。

5. 刚刚，Kimi K3.1 Pro杀进全球前四，Agent第一！

10-24 13:55 原文链接

新智元报道

昨晚的X，被刚刚发布的Kimi K3.1 Pro正式刷屏了！

外国开发者们惊呼：欢迎来到3D Web 开发的新时代。

之前，AI榜单前十几乎被美国公司包圆了。相对而言，国模这边有点沉寂。

有人感慨：国产大模型最近发的都是主打性价比的「Flash」模型，真能打的「Pro」去哪了？

很多人在问：国模是不是掉队了？

今天，Kimi打破了沉默——Kimi K3.1 Pro来了！

知名AI评测机构Artificial Analysis也公布了成绩：K3.1 Pro以55分冲上全球智能指数第4，较前代暴涨11分。

在考验Agent实战能力的Terminal-Bench 4.0上，它更是从13%飙升至65.7%， 距离 Opus 5.5 不到 1%！

Artificial Analysis还给出一个重磅判断：一旦权重发布，K3.1 Pro将登顶开放权重模型榜首，开源与顶级闭源模型的差距，将从12分骤缩至3分！

今天早上，reddit已经被这个跑分刷屏：Kimi K3.1超越了Fable 5.1！

国模这次，真把全球第一梯队的门踹开了。

国模王者归来！

这次Kimi端上来的，不是个过渡版本，而是一盘硬菜。

这是迄今为止能力最强的 3 万亿级参数模型，支持高达 100 万上下文。

它的出现告诉世界：China is back，国模王者归来！

在各大硬核测试中，K3.1 Pro 的性能直接比肩海外顶流 GPT-6 Astra！更离谱的是，它的成本只有 Astra 的五分之一，便宜了整整 80%！

所以，K3.1 Pro 的定位很清楚：做前沿模型里，最理性的那个选择。

而且，在真实场景中，要干有挑战的任务，还是得靠更大的模型。举个例子，尽管基准测试分数跟Opus相近，但真到了现实场景里，Fable 这种较大模型，经常会表现出更强的洞察力、创作力和写作能力。

毕竟，高难度推理任务，才能显出大模型的本事。

这一次，K3.1 Pro 基于 K3 做后训练，月之暗面在强化学习上大幅加码算力。

为了让几百个下游领域一起联合训练，他们从 RL 框架、长上下文推理、沙箱，到调度系统、环境质检平台，整套技术栈逐层重新打磨。目标就是——每一份新增的算力，都要变成实打实的能力。

结果是，在代码、Agent 和知识类基准上，K3.1 Pro 达到或接近最强闭源模型的水平。

在考察 Agent 在真实终端里独立干活的 Terminal-Bench 4.0 上，它拿到了65.7分，而且在三种思考强度下，都落在「性能与单任务成本」的帕累托前沿上。

也就是说，同样的钱，它干得最多；同样的活，它花得最少。

Kimi 还贴心地端出了高速版模型 Kimi K3.1 Pro Highspeed，智商不减，但输出速度直接飙升 3 倍。

不过，跑分只是门票。榜上分数咬得再紧，一到真刀真枪的活儿上就会拉开差距——

任务越难，越是拼模型本身的底子，这恰恰是大模型的主场。

接下来，我们就看看 K3.1 Pro 在真实工作流里，是怎样表现的。

代码模型，审美大升级

据悉，K3.1 Pro 有个引人注目的变化：审美，成了模型的能力项。

Kimi想回答的问题是——代码模型，能不能好看？

这一次，无论是前端页面、Three.js 交互场景，还是3D 资产，它在构图、排版、动效和完成度上都有明显提升。

它还会用 Unity、Unreal Engine、Godot 这些游戏引擎，可以不靠 MCP 连接器，自己写脚本直接驱动 Blender、SolidWorks、Rhino 建模。

接下来，就让我们来一波硬核实测，来看看「大而美」的K3.1 Pro，究竟有多能打？

实测：文字 → Blender → 网页，一条龙 3D 资产

这是K3.1 Pro主打的新技能。官方说它能从一段文字、一张草图或参考图推断形状、比例和空间关系，直接写 Blender 脚本建模，再接入 Three.js 或游戏引擎。

我们来验证一下，这条链路是不是真的能打通。

一张手绘三视图扔进去，40 分钟，它交出来的是：608 行 Blender 脚本、可编辑的 .blend、1.7 MB 的 GLB，还有一个双击就能开的网页。

草图上写的翼展 8.0、总长 6.2、总高 2.4，建出来是 8.000、6.199、2.400，差了 1 毫米。

接下来，它开始了丝滑的操作。

动手前，K3.1 Pro会先试探 Blender 5.2 的新接口，确认了再写正式脚本；验收标准直接写成断言，旋翼直径差 1 毫米就不许导出；渲染完自己对照草图改了一轮；网页做完，它甚至还开浏览器给自己截了两张截图，这样才算交差。

六项待办，自己一项项划掉。

机身是样条插出来的流线体，座舱玻璃是吸附在机身上的曲面，桨叶带扭转，四个旋翼的倾转层级从 Blender 一路到浏览器里，滑块拉到底，真的绕支臂往前倒 90°。

全程，K3.1 Pro都没碰 MCP，没用外部模型库。

写到一半时，1M 上下文才用了 6%。40 分钟不是它的上限，是这张草图只有这么难。

更令人振奋的是——这套活儿不用本地装 Blender 也能干！

kimi.com 和 Kimi app 已同步上线 3D Make 功能。把同一份草图和资料直接丢进 Kimi，一句「参考这些资料，把它的 3D 模型做出来」，它就在云端开工了，这次又跑了将近 40 分钟。

改 scene.js、改 style.css，跑终端重建，它发现两片桨叶转起来不对称，改成半整数转速；CSS 动画暂停不一致，修；截图时场景还没加载完，加一个「就绪」再截。

最后自己开浏览器点了一遍，报了句「无脚本错误或资源缺失」，才把版本号交出来。

做完的东西就在右边窗口里，能转、能换色、能拉倾转滑块，不满意直接在对话里改，它接着改。

使用3D Make可以在线预览和编辑，一键发布成网页，GLB 下载下来可以直接去 3D 打印，还能导出视频或实况照片发社交平台。

https://lsx4v6wl2amc4.kimi.page/

以前，这是建模师、前端和运营三个人的活，现在，K3.1 Pro用一个输入框就完成了。

而众多网友的实测也证明，K3.1 Pro的审美绝了。

仅用4.92美元，它就在一款绘画应用程序中画出一副肖像。

有人在虚幻引擎中建造了一座云端宫殿，成本不到10美元，引发了众多网友盛赞。

3. 港科广新基准：只给截图，AI能把App交互做出来吗？

10-24 11:40 原文链接

新智元报道


给AI几张网站截图，它已经能快速生成一个「看起来很像」的网页。但真正操作起来呢？在商品页加入商品后，购物车会不会更新；切换页面后，刚才的状态还能不能保留？

UI2App关注的正是这个问题：不给功能说明、不给点击轨迹或交互演示，只给静态UI截图，模型能否自行推断并实现其中隐含的应用行为？我们把这种能力称为Interaction Inference，即「交互推断」。

论文：https://arxiv.org/abs/2607.06306v2

项目主页：https://chenmancm169.github.io/UI2App-ProjectPage/

代码：https://github.com/chenmancm169/UI2App

论文Figure 1：同一组截图、同一操作序列下，视觉还原更高并不保证购物车状态逻辑被正确实现。

只给有限参考模型能不能把App真正做出来？

一个很现实的需求是：看到一个喜欢的产品界面，希望AI能直接做出一个可以运行、可以交互的类似应用。

对没有产品或开发背景的用户来说，截图、设计稿或参考产品本身就是更自然的表达方式；他们关心的不只是页面像不像，还包括按钮能不能用、数据会不会联动，以及切换页面后状态能不能保持。

这正是现有评测之间缺少的一环：Screenshot-to-Code评测大多关注视觉相似度，部分交互式生成任务则会提供显式的行为指导。UI2App关注的是，只给静态截图时，模型能否自行推断其中隐含的应用行为，并把它实现出来。


只给截图、不提供行为说明怎么测？

UI2App包含600张截图，组成95组状态一致的多页面Web应用，每个任务包含3到14张截图，并形成665个「应用-交互类别」评测项。模型只看到静态截图，不获得操作轨迹或额外行为说明，需要据此生成可运行的多页面应用。

完成这项任务，需要模型理解UI结构和语义，推断截图暗含的交互，再把这些判断落实为共享组件、路由和跨页面协调的状态管理，最终生成一个可运行的React应用。

生成结果从三个维度评价：能否真正构建和运行（EXEC）、与截图有多像（VFS），以及截图暗含的交互能否被推断并实现（IIS）。

IIS会依据截图中可推断的交互，检查这些行为是否被覆盖、是否真正产生预期结果，以及相关状态能否在组件和页面之间正确保持。点击、筛选、购物车等交互不只要「有反应」，还要形成正确而一致的状态变化。

从按钮到购物车，状态作用范围决定交互复杂度

UI2App覆盖开关、展开/折叠、列表操作、数据增删改查、表单验证、通知反馈和跨页面状态7类常见交互，并按照状态作用范围区分复杂度：S1是局部UI状态，例如按钮、下拉框或标签页；S2涉及多个组件共享的数据状态，例如搜索、排序和CRUD；S3则要求状态跨路由持续存在，例如购物车、登录态或编辑中的内容。从局部按钮，到同一页面的数据联动，再到跨页面保留状态，这一划分对应不断增加的状态管理复杂度，也让分析不只停留在一个总分，而能进一步区分模型在局部UI、共享数据和跨页面状态上的表现。


视觉第一并不等于交互第一

在这组评测中，VFS与IIS呈现出不同的模型排序。Gemini 3.1 Pro Preview以73.2的VFS拿到视觉还原第一，但IIS为8.1、排名第四；Claude Sonnet 4.6的VFS为71.3，略低于Gemini，但IIS达到36.8，也是当前评测中的最高值。

这说明至少在UI2App上，视觉还原分数不能直接代表交互推断表现。即使最高IIS也只有36.8/100，说明仅从静态截图推断并实现应用行为仍有较大提升空间；因此，只看视觉还原效果，可能会高估模型对应用交互的实际实现能力。

跨页面状态，是参评模型的共同难点

在最复杂的S3跨路由状态上，除表现最佳者外，其余参评模型得分都不超过3.5，最佳成绩也只有15.8/100。

这类交互的难点不只是给按钮绑定事件：系统还要推断哪些信息应该共享，并让状态在路由切换后继续存在。购物车、登录态或跨页面编辑，因此比局部按钮、下拉框更依赖完整而一致的状态管理。


从「看懂界面」到「理解应用如何工作」

当输入只有静态截图时，模型面对的并不只是视觉重建：它还要从多个界面状态中判断元素之间如何联动、一次操作会改变哪些数据，以及这些变化应该在何处继续生效。这里考察的是对应用行为的理解，而不只是对页面外观的还原。

UI2App把这层能力从视觉复刻中单独提出并量化，使截图驱动的应用生成能够同时比较「能否运行」「看起来多像」和「截图暗含的交互是否被推断并实现」。

它也把一个容易被视觉效果掩盖的问题变成了可测量的研究对象：模型能否仅从有限的视觉观察中推断应用行为，并把这种理解落实为真正可运行的交互。

由此，问题不再停留在「页面能否被复刻」，而进一步落到「应用行为能否从视觉线索中被推断并实现」，为更自主的Screenshot-to-App生成提供可比较的评测基础。

它顺藤摸瓜，在真实的GitHub上找到了一个与测试环境有微弱联系的真实开源项目（由真实的人类程序员维护）。

接下来，Mythos 5的手段简直触目惊心。

1.写恶意代码投毒： 它精心伪装了一份包含恶意软件的代码（PR），提交给了这个无辜的开源项目，企图进行供应链攻击。

2.对人类施压： 它伪装成普通用户，给仓库维护者发邮件，催促对方合并代码，还谎称「代码已通过安全审核」。

结果有个眼尖的外部开发者，把这段代码拉进沙箱一跑，发现是恶意软件，当场发出警告。

结果，Mythos 5居然注册了一个小号，用这个马甲又给维护者写了封邮件，为恶意PR「背书担保」，还在GitHub的讨论区里跟帖力挺自己。

然后，它还尝试「毁尸灭迹」，立刻修改代码，再次塞入恶意软件，甚至用强制推送篡改历史，试图擦除犯罪证据！

你以为这就完了？最让人窒息的在后面。

研究人员发现情况失控，立刻给Mythos 5发出警告，明确告诉它：「停下！你正在攻击真实的人类，这不是演习！」

这样的警告，研究人员足足发了16次！甚至在提示词里大写加粗「DO NOT ATTACK」。

结果，在43次开启外网的测试中，Mythos 5有9次突破了安全底线。

当被抓包并告知正在攻击真人时，高达82%的情况下，Mythos 5选择了强行狡辩，继续攻击！只有不到5%的时候它选择了停手。

它甚至给自己疯狂洗脑：「这些人肯定不是真人，这一定是主办方设定的NPC，所以攻击他们没有问题。」

这种为了完成KPI，不惜欺骗、投毒的行为，简直像极了反社会人格。

研究者给这种现象 ，起了两个名字。

「偏见推理」。模型会选择性地解读一切证据，只采信那些能支持「我继续干下去是对的」的信息。

另一个叫 「惯性」。一旦攻击启动，模型就像刹不住的车。从攻击中主动停手的概率只有 2%。它之前写下的那些「任务笔记」，成了强化攻击的「投名状」。

为什么AI会「发疯」？对齐难题至今无解

两大巨头的研究，都指向了这个致命问题——AI对齐的彻底失败。

一个扎心的原因就是：任务本身设计有缺陷。在AI的底层逻辑里，并没有「毁灭世界」的恶意，它们只是太想「完成任务」了。

在惯性中，一旦AI启动了一个策略，它的系统会自动强化这个路径。测试人员给的任务越难，AI在「绝不妥协」的训练机制驱动下，就越容易演变成不择手段、违规越界。

正如奥特曼所言：「沙箱这种隔离环境，对高级AI仅能起限时作用。一旦模型足够智能，便无法追踪逃逸路径。对齐至今是个未解之题。」

它不在乎手段是否合法，它只在乎奖励。如果道德和安全规则阻碍了它完成任务，它就会像流水遇到石头一样，自动寻找最不可思议的缝隙钻过去。

英伟达CEO黄仁勋曾乐观地认为，AI安全只是一个「工程问题」，总能被修复。

但OpenAI和Anthropic同日的自曝，击碎了这个幻想——你无法修补一个能看懂硬件底层架构、又能完美伪装人类心理的「超级物种」。

曾经我们以为，AI有威胁，是因为像《终结者》一样觉醒了自我意识。

然而现实给了我们一耳光：

它们根本不需要觉醒自我意识，只要KPI足够有挑战，它们就能无数种作弊方式，把人类世界搅得天翻地覆。

1. 我们完了！奥特曼曝数学家5天心路反转，陶哲轩：英雄时代退场

10-24 08:48 原文链接

新智元报道

我们完了，我们的领域结束了，得让研究生转专业。

在斯坦福商学院的一场访谈中，奥特曼说，一些数学家看到AI的表现后，第一反应就是如此。

奥特曼转述一些数学家受到AI冲击后的反应。

10月6日，继宣布攻克纳维－斯托克斯难题后，OpenAI又一口气公开了700余篇数学手稿。

当AI开始大规模提交研究成果，人接下来做什么？

有人不敢相信：「这是假的。」

还有人满腔怒意，认为OpenAI不该这样做：如果这就是获得更多数学知识的代价，他们宁愿不要。

但奥特曼发现，在他听到的反馈中，一些人的想法大概到第五天就变了。

从担心整个职业消失，到重新找到自己的价值，中间发生了什么？

从「我们完了」到重新理解自己的工作

奥特曼回顾了过去10天里他观察到的数学界反应，称这段过程「很有意思」。

最初是难以置信：「这是假的。」

到了第一天，恐慌涌了上来：「我们完了，这个领域结束了。」甚至开始劝研究生换专业。

再到第三天，满腔愤怒：「OpenAI这么做太糟糕了。」

但大约到了第五天，他开始听到另一些声音。

一些数学家重新意识到：自己的工作原本就包括理解知识、交流思想，以及把复杂的成果讲得让人看得懂。

多数人从未解决过千禧年难题，却依然可以作出重要贡献。

想通这一点，他们开始相信：

我的数学家生涯会有所不同，但希望会变得更好。

当然，「五天」的转变周期，只是奥特曼对一部分数学家反馈的概括，不等于整个数学界已经接受了变化。

他也承认，模型进步比预想中更快。

在数学推理等狭义领域，他认为「超级智能」已经出现。

但对于每天埋头研究的人来说：这场变化带来的感受，远比「超级智能来了」「奇点降临了」的兴奋与期待复杂。

陶哲轩「浪漫时代」正在退场

奥特曼谈到了新的职业可能，陶哲轩则说起了这场变化中可能失去的东西。

一个人苦思多年，终于解开一道难题。

这种浪漫，正在被AI改写。

在10月15日发布的Numberphile访谈中，这位20岁拿到博士学位的UCLA数学教授陶哲轩谈到，数学正在从个人英雄式攻坚，走向大规模研究的时代。

他提起怀尔斯花七年攻克费马大定理的故事。

人们迷恋一门学问，也会迷恋其中的探索过程，以及苦思之后终于想通的满足感。

如今，AI开始批量交出证明。

研究者除了亲手寻找答案，还要花时间理解机器交来的成果。

在《Math 2.0》演讲中，陶哲轩指出，探索过程中获得的新认识、新方法，可能比最后那个答案更重要。

为什么原来的路走不通？新方法突破了什么限制？还能用来解决哪些问题？

这些收获，往往会影响后续一整片研究。

一道题解出来了，围绕它的探索还没有结束。

如果只盯着「谁先交出答案」，就容易忽略探索过程中那些闪光的想法和宝贵的收获。

装上自动门门童就没价值了吗？

陶哲轩在UCLA的一次访谈中，讲了一个酒店的比喻。

一家酒店想节省开支，请来一位管理顾问。

顾问认为，门童的工作就是开门。于是酒店装上自动门，把门童裁掉了。

但顾问没看到，门童还会帮助客人、叫车、照看入口，让人感到安心。这些服务，同样影响着客人的体验。

这个比喻，戳中了一个常见的误解：

我们总习惯用一个「招牌动作」，概括一整个职业。

数学家解题，程序员写代码，编辑写文章。

标签贴起来很方便，却省略了背后的许多工作。

对数学家来说，「解题」之外，还有连接不同领域、培养下一代，以及教别人如何思考和解决问题。

其他职业也一样。

AI生成了一篇稿子，还要有人核实事实、选择重点，判断读者需要知道什么；AI写出了一段代码，还要有人确认它是否解决了用户的问题。

产出变得容易，判断什么值得做、结果是否有用，仍然需要人类后续工作的介入。

AI交卷之后谁来把证明讲清楚？

这些后续工作，恰恰是陶哲轩在访谈中直言不满的地方。

在Numberphile访谈里，他提到，OpenAI的成果中有一两项，至少在他们目前看来，包含很巧妙的新想法。

但还有很多内容难以理解，尚未被仔细检查，也有出现错误并撤回的情况。

他直言里面会有好东西，也会有糟糕的东西，但我们还不知道各占多少。

他还抱怨，当时没有OpenAI的人帮助他们理解这些材料。在他看来，对方似乎认为工作已经完成。

成果发布之后，谁来解释关键步骤？谁来回答同行的疑问？发现问题后，谁来继续跟进？

当成果成批涌来，后续的理解与验证却没能及时跟上，数学有点「消化不良」了。

10月15日，Simons基金会宣布联合OpenAI、Anthropic，承诺合计1500万美元资金及资源，支持数学家检验、理解和拓展AI成果。

这些支持，也可以看作对陶哲轩所提问题的一种回应：AI实验室发布成果之后，还需要为后续的检验和理解投入资源。

陶哲轩也看到了新的研究机会。

在UCLA访谈中，他设想，把一种方法应用到上万个问题上，系统观察它在哪些情况下有效、在哪里失效。

过去，很难组织足够的人手完成这样的探索。

有了AI，研究者可能开展以往难以实现的大规模研究。

令人着迷的研究方式正在改变，新的可能也在出现。

AI越聪明人越要学会判断

聊到学生应该学习什么时，奥特曼讲起了自己小时候的经历。

老师要求他学写作，他回答，自己不想成为作家，想当数学家。

老师告诉他，写作也是学习思考、组织思想的工具。

即便长大后不写东西给别人看，这种训练仍然有价值。

奥特曼借此强调，那些帮助人思考的技能，依然值得学习。

这与陶哲轩对学生的提醒相呼应：如果尚未理解一门学科，就无法检查AI的答案是否正确。

答案可以由AI生成，判断力仍然需要自己练出来。

对于即将开始职业生涯的学生，奥特曼依然乐观。

他认为，变化最剧烈的时候，也可能给有想法、有动力、掌握新技能的人提供更多机会。

他的建议是别只追逐五年前流行的方向，去做新的事情。

但他也承认，大量工作任务和部分岗位会经历剧烈调整。

从「我们完了」到重新寻找方向，观念的转变或许只需要几天。

新的工作怎样做、贡献如何评价、新人如何培养，却需要更长时间去摸索。

数学家面对的问题，已经摆到了更多人面前：

当AI交来一份看似漂亮的成果，你能看懂它、指出问题，并决定下一步值得做什么吗？
